# Data contracts (D1, F1)

Machine-readable JSON Schemas: `contracts/*.schema.json` (generated by `python -m app.contracts`), also served at
`GET /v1/contract` and in OpenAPI at `/docs`. Contract version: `petition.v1`.

## POST /v1/petitions  (request: `petition.request.schema.json`)
| field | type | rule |
|---|---|---|
| client_petition_ref | string? | `^[A-Za-z0-9_-]{1,64}$`, idempotency key |
| student_ref | string | `^SYN-\d{6}$`: **synthetic ids only**, so real records cannot enter |
| program | enum | BTECH, MTECH, MBA |
| admission_batch | int | 2015 to 2030 |
| semester | int | 1 to 8 |
| course_code | string | `^[A-Z]{2,4}\d{3}$` |
| course_type | enum | theory, lab, project (default theory) |
| declared_type | enum? | attendance, re_evaluation, re_registration, medical_leave, grade_grievance |
| grounds | enum | medical, sports_duty, personal, academic, none |
| description | string | 10 to 1500 chars; free text, scanned by guardrails |
| submitted_on | date | not in the future |
| classes_held / classes_attended | int? | 1 to 300 / 0 to 300; **supplied together; attended ≤ held** |
| attendance_percent | float? | 0 to 100; **must match attended/held ± 0.5** if both given |
| duty_classes | int? | **attended + duty ≤ held**; needs classes_held |
| prior_condonations | int | 0 to 10 |
| medical_certificate_attached | bool | |
| days_since_resumption | int? | 0 to 365 |
| days_since_result | int? | 0 to 365 |
| prior_reevaluations | int | 0 to 5 |
| grade_obtained | enum? | S A B C D E F DT |
| attempts_used | int? | 0 to 10 |
| leave_days | int? | 1 to 730 |
| (any other field) | | **rejected** (`extra=forbid`) |

Required by declared type (cross-field): attendance → attendance_percent or held/attended; re_evaluation and
grade_grievance → days_since_result; re_registration → grade_obtained; medical_leave → leave_days.

Responses: **202** `{run_id, status, status_url, cached}` · **422** `{error, contract, quarantine_id, errors:[{field, error}], run_started:false}` · **429** `{retry_after_s}`.

## GET /v1/runs/{run_id} → `{run_id, status, created_at, updated_at, e2e_seconds?, result?}`
`status`: queued | researching | adjudicating | completed | failed. `result` follows `run.result.schema.json`:
`route` (grant-under-provision | refer-to-committee | reject-with-cited-clause | escalate-to-human),
`eligibility_position`, `basis`, `rationale`, `citations[{clause_id, doc_title, chapter, chapter_title, heading, quote, role}]`,
`escalation{required, reason_code, reason, path[]}`, `verification{passed, rounds, checks[]}`, `degraded`,
`decision_authority: "examination_officer"`, `prompt_versions`, `corpus_version`, `guardrail_flags`, `cost`.

## POST /v1/feedback  `{run_id, satisfactory: bool, reason: 3-500 chars}` → aggregated at `GET /v1/feedback/summary`

## Internal: Redis stream messages
`stream:research {run_id, strategy: primary|alt, round, feedback, carrier}` · `stream:adjudicate {run_id, round, carrier}`
(`carrier` = W3C trace context, so the trace continues across services).
